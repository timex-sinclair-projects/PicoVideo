01Installing the board

PicoVideo needs no software. Once it is plugged in, everything the TS2068 shows appears on the VGA monitor.

  1. Switch the TS2068 off.
  2. Plug PicoVideo into a slot on your expansion bus, ideally with the bus off the computer.
  3. Plug the bus firmly into the TS2068's expansion connector.
  4. Connect PicoVideo's VGA connector to a VGA monitor or a VGA-to-HDMI converter.
  5. For sound, run a 3.5 mm cable from PicoVideo's audio jack to the monitor, converter or speakers. The jack carries the TS2068's audio.
  6. Switch on the monitor, then the TS2068.
Off before you plugNever plug PicoVideo in or out with the TS2068 switched on.

02Everyday use

You don't have to do anything. There is no driver to load and no mode to set. PicoVideo copies the picture as the TS2068 draws it, so BASIC, games, utilities and Spectrum programs run through an emulator all appear on the monitor as they are. Load them the way you always have. The TS2068's own video output keeps working.

  • Every TS2068 mode shows as it does on a television: the second display file, extended color and 64 columns (section 5).
  • Spectrum programs: Speccy Black starts on, so BRIGHT black looks black, not dark gray (section 6).
  • Sound comes out of the audio jack, including the LOAD and SAVE tones.

What can look different

PicoVideo draws 60 pictures a second at its own pace, not in step with the TS2068's television scan.

  • LOAD and SAVE: the border still changes color, but the stripes are a different width and move differently.
  • Effects timed to the beam: demos and games that change the border or colors partway down the screen show without those effects.
  • Paged banks: writes to the screen area while a dock or EXROM bank is paged over it don't show. Few programs do this.
If the picture looks wrongPicoVideo keeps its settings until it is switched off. If a program leaves it in an odd mode or colors, switch the TS2068 off and on again.

03How PicoVideo works

PicoVideo never takes over the TS2068's video: it watches the bus. A PLD on the board passes every write to 4000h–7FFFh and every I/O request to the Pico. One core keeps a copy of video memory and of ports $FE, $FF and $F4; the other draws a 640×480 VGA picture from that copy 60 times a second.

  • It sees writes, not reads. Its copy changes only when the Z80 writes. Register 72 reads the copy back (section 12).
  • It copies only the home bank. While a program pages a dock or EXROM bank into 4000h–5FFFh or 6000h–7FFFh (port $F4 bits 2 and 3), PicoVideo ignores writes there. The same goes while a TS-2068 Megabank bank owns either chunk: PicoVideo follows its owner registers (ports $FD and $FC).
  • Its timing is its own. Effects timed to the TV beam, such as border stripes and mid-screen color changes, don't line up (section 2).
  • It keeps its settings. NEW and the end of a program don't clear its registers. A program that changes one should put it back.

The screen

The 256×192 screen is shown at 2× (512×384) in the middle of the 640×480 picture, with the border around it. Modes 6 and 7 use the same area at 512 pixels across. Mode 5 is 640 pixels wide and fills the screen from side to side.

FLASH swaps INK and PAPER every 32 VGA frames, about twice a second. With the ULAplus palette on, the FLASH bit picks colors instead.

04Talking to PicoVideo

PicoVideo uses the two ULAplus ports, decoded on all 16 address bits. Write a register number to $BF3B (48955), then read or write its value at $FF3B (65339).

PortDecWriteRead
$BF3B48955Select a registerThe selected register number
$FF3B65339Set the registerIts value, or 255 if not readable
OUT 48955,66: OUT 65339,1: REM set register 66 to 1
OUT 48955,64: PRINT IN 65339: REM read register 64

Finding the board and its version

Register 127 holds the version as two hex digits: $46 (70) is 4.6. A board that's present also reads the selected register back from port 48955. Firmware V4 reports 1.0.

picovideo.h

/* picovideo.h, shortened: the full file in examples/c/ also
   defines each register, PV_ULA_ENABLE 0x40, PV_MODE 0x41,
   PV_SPECCY_BLACK 0x42, PV_MIRROR 0x43, PV_INDEX_LO 0x44,
   PV_INDEX_HI 0x45, PV_FONT_DATA 0x46, PV_QUAD_COLOR 0x47,
   PV_VIDEO_READ 0x48 and PV_VERSION 0x7F, and the pointers
   DF1 (0x4000) and DF2 (0x6000). */
#define PV_SELECT  0xBF3B   /* write the register number here */
#define PV_DATA    0xFF3B   /* then read or write its value here */
void pv_write(unsigned char reg, unsigned char value) {
    outp(PV_SELECT, reg); outp(PV_DATA, value); }
unsigned char pv_read(unsigned char reg) {
    outp(PV_SELECT, reg); return inp(PV_DATA); }
/* Set the video mode in port $FF, keeping bits 3-7. */
void pv_mode(unsigned char mode) {
    outp(0xFF, (inp(0xFF) & 0xF8) | mode); }

05The TS2068 modes

The low three bits of port $FF pick the video mode. PicoVideo watches the same port, so the TS2068's own modes work as always, and it adds new modes in the numbers the TS2068 doesn't use.

ModeShowsMemory
0Normal 32 columnsDF1: 4000h, attrs 5800h
1Normal, second display fileDF2: 6000h, attrs 7800h
2Extended color: an attribute per pixel lineDF1 pixels, DF2 attributes
3New: quad color, 256×192DF1 and DF2, linear
4Not used; shows mode 0—
5New: 80×24 textDF1 only, linear
664 columns, one color pairDF1 even, DF2 odd columns
7New: 64 columns with attributesDF1 and DF2 with attributes

Keep the other bits of $FF when you change mode: bits 3–5 are the mode 6 colors, bit 6 turns interrupts off, bit 7 selects dock or EXROM. In BASIC they are normally 0, so OUT 255,mode is safe.

In mode 6 the screen has one INK and PAPER: OUT 255,6+8*n gives INK n on PAPER 7−n, never BRIGHT.

Display file 2 and BASIC

Modes 1, 2, 3, 6 and 7 read DF2 at 6000h–7AFFh. With one display file, that memory holds the machine stack, system code, channel data and the start of your BASIC program, and PicoVideo shows it as noise. To use DF2 from BASIC, set the TS2068 up for two display files first, which moves BASIC up to 7B00h (TS2068 Technical Manual, Appendix C). Machine code and C above 8000h can write to DF2 directly.

06Colors and Speccy Black

Without the ULAplus palette, PicoVideo draws the 16 TS2068 colors from a built-in table.

The photo palette

Normal colors give about half the light of BRIGHT, measured on a VGA monitor in sRGB mode. BRIGHT colors are unchanged. It starts with Speccy Black on and a white border. The 4.3 and 4.4 releases have an earlier version, in which normal blue, red and magenta match BRIGHT. Built with PICOVIDEO_PHOTO_PALETTE=OFF, it uses the original colors and starts with Speccy Black off.

Speccy Black

A ZX Spectrum shows BRIGHT black as black; a TS2068 shows it as dark gray, so Spectrum programs can show gray patches. Speccy Black draws BRIGHT black as black. Register 66 turns it on (any value but 0) or off (0). It can't be read back and does nothing while the ULAplus palette is on.

07The ULAplus palette

With the ULAplus palette on, attributes take their colors from a table of 64 that you load. The 64 entries are four tables (CLUTs) of 16. FLASH and BRIGHT choose the table; within it, entries 0–7 are INK and 8–15 PAPER.

FLASHBRIGHTTableINKPAPER
00CLUT 00–78–15
01CLUT 116–2324–31
10CLUT 232–3940–47
11CLUT 348–5556–63

INK 3; BRIGHT 1 uses entry 19; PAPER 2; FLASH 1 uses entry 42. The border uses CLUT 0's PAPER: BORDER 4 shows entry 12.

  • Registers 0–63 are the entries, each a color byte (32×green + 4×red + blue; green and red 0–7, blue 0–3). Readable.
  • Register 64 turns the palette on (not 0) or off (0). Readable.
Load firstEvery entry is 0 (black) at power-on. Switch the palette on before loading it and the screen goes black.

08Quad color (mode 3)

Mode 3 is 256×192 with any of four colors per pixel and no attributes. Each pixel is two bits.

  • Pixel line y starts at 4000h+32y in DF1 and 6000h+32y in DF2, in order from top to bottom.
  • Pixels 0–3 of each 8-pixel group come from the DF1 byte, 4–7 from DF2.
  • Bits 7–6 of a byte are the leftmost pixel, bits 1–0 the rightmost.

The four colors

Register 71 holds four color bytes. Set the index to 0 with register 68, select 71 and write four values; the index steps on each time. They start as black, white, green and yellow (0, 255, 224, 252). Register 71 can be read back.

OUT 48955,68: OUT 65339,0
OUT 48955,71: OUT 65339,2: OUT 65339,199: OUT 65339,59: OUT 65339,252

0964 columns in color (mode 7)

Mode 6, the TS2068's 64-column mode, has one INK and PAPER for the whole screen. Mode 7 uses the same 512-pixel layout plus the attribute areas of both display files, so every column has its own INK, PAPER and BRIGHT.

  • Even columns use DF1: column c is byte c/2 of a normal screen line at 4000h, attribute at 5800h.
  • Odd columns use DF2 the same way, at 6000h and 7800h.

Fill the attribute areas before you switch to mode 7. The example takes its character shapes from the ROM, through CHARS at 23606.

1080-column text (mode 5)

Mode 5 is 80 columns by 24 rows. You store character codes; PicoVideo draws them with its own 8×8 font, which starts as the IBM PC code page 437 set. Each character has a normal TS2068 attribute.

WhatAddressesFormula
Codes16384–1830316384+80×row+col
Attributes18304–2022318304+80×row+col

Mode 5 uses only the first 3840 bytes of DF1, so it works from BASIC, and BASIC's reports at the bottom of the TS2068 screen don't disturb it. CLS fills it with 0: blanks in black on black, so fill the attributes before you print.

11Changing the font

The 80-column font is 2048 bytes in the Pico: 256 characters of 8 bytes, top row first, bit 7 leftmost. Character c starts at byte 8c.

  1. Write the start address to registers 68 (low byte) and 69 (high byte).
  2. Select register 70 and write the bytes. The address steps on each time and wraps from 2047 to 0.

To load a whole font, use pvLoadFont from picovideo.asm. A changed font lasts until power-off.

One index for three registersRegisters 70 (font), 71 (quad colors) and 72 (video memory) share the index in registers 68 and 69. Set it again when you switch between them.

12Mirroring and readback

Register 67 turns mirroring on (not 0) or off (0); it can be read back. While it is on, writes to 4000h–5FFFh go into PicoVideo's DF2 instead of DF1. The TS2068's own memory changes as usual. This lets routines that only know DF1, like the ROM's PRINT and PLOT, draw into DF2. It doesn't change the mode, and writes to 6000h–7FFFh still reach DF2.

Register 72 reads PicoVideo's copy of video memory, which PEEK can't. Set the index with registers 68 and 69 (0 is 4000h, 8192 is 6000h), select 72, and each IN returns a byte and steps on. Before 4.6, reads of registers 70–72 can be wrong.

13Pinning the mode

Register 65 fixes the video mode so that port $FF can no longer change it. It works only while the ULAplus palette is on; with it off, $FF always sets the mode. It can be read back.

Register 65Video mode
0Follows port $FF (the starting value)
128Fixed at mode 0

Flashing the Pico

  1. Switch the TS2068 off and take PicoVideo out of the bus.
  2. Hold down BOOTSEL on the Pico while you plug a Micro-B USB cable into the Pico and your computer, then let go.
  3. Drag the .uf2 onto the RPI-RP2 drive. When it disappears, unplug the cable and put the board back.

Building it yourself

You need the Pico SDK, arm-none-eabi GCC, CMake and Ninja:

cmake -S firmware -B build -G Ninja \
  -DPICO_SDK_PATH=/path/to/pico-sdk
ninja -C build

The result is build/picoTsVid.uf2. For the original colors, add -DPICOVIDEO_PHOTO_PALETTE=OFF.

Untested on a board: mode 1, $F4 and Megabank paging, other boards, non-default builds and general software compatibility. Report problems on the project's GitHub page.

ULAplus is a ZX Spectrum standard. PicoVideo follows its palette registers (0–64); registers 65 and up are PicoVideo's own.
