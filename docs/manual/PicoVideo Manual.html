PicoVideo

PicoVideo is a TS2068 expansion board that watches the computer's bus and redraws its screen as clean VGA, using a Raspberry Pi Pico. On top of the TS2068's own video modes it adds a 64-color ULAplus palette, a four-color mode, 64 columns with full color and an 80-column text screen with a font you can change.

01Installing the board

PicoVideo needs no software to work. Once it is plugged in, every program you run on the TS2068 appears on the VGA monitor.

  1. Switch the TS2068 off.
  2. Plug PicoVideo into a slot on your expansion bus. It is easiest to do this with the bus off the computer.
  3. Plug the bus firmly into the TS2068's expansion connector.
  4. Connect PicoVideo's VGA connector to a VGA monitor, or to a VGA-to-HDMI converter.
  5. For sound, run a 3.5 mm cable from PicoVideo's audio jack to the monitor, converter or speakers. The jack carries the TS2068's own audio.
  6. Switch on the monitor, then the TS2068. The copyright screen appears on the monitor.
Off before you plugNever plug PicoVideo in or out with the TS2068 switched on.

02Everyday use

You don't have to do anything. PicoVideo has no driver to load, no mode to set and no command to type. It copies the picture as the TS2068 draws it, so BASIC, games, utilities and Spectrum programs run through a Spectrum emulator all appear on the VGA monitor as they are. Load them from tape or disk the way you always have. The TS2068's own video output keeps working, so a television can stay connected too.

What you see

  • The picture. The 256×192 screen is shown at twice its size in the middle of the VGA picture, with the border around it. The colors are measured from a real TS2068's RGB output, so the picture looks like the computer's own.
  • Every TS2068 mode. Programs that use the second display file, extended color or 64 columns show on PicoVideo just as they do on a television (section 5).
  • Spectrum programs. PicoVideo starts with Speccy Black on, so BRIGHT black looks black, as it does on a Spectrum, instead of the TS2068's dark gray (section 6).
  • Sound. The audio jack carries the TS2068's sound, including the tones you hear during LOAD and SAVE.

What can look different

PicoVideo draws its picture at its own pace, 60 times a second, not in step with the TS2068's television scan. A few effects depend on that timing:

  • The border during LOAD and SAVE. The border still changes color, but the stripes don't line up the way they do on a television. They are a different width and move differently.
  • Effects timed to the beam. Some demos and games change the border or the colors partway down the screen, in time with the television's beam. PicoVideo shows the screen without those effects.
  • Drawing into a paged bank. A program that writes to the screen area while it has a dock or EXROM bank paged over it isn't drawing on the screen, and PicoVideo ignores those writes too. Most programs never do this.
If the picture looks wrongPicoVideo keeps its settings until it is switched off. If a program changes them and doesn't put them back, later programs can look wrong: in the wrong mode, or in the wrong colors. Switch the TS2068 off and on again to start fresh.

03How PicoVideo works

PicoVideo never takes over the TS2068's video. It watches the bus. A PLD on the board passes every write to video memory (4000h–7FFFh) and every I/O request to the Pico. One core of the Pico keeps its own copy of video memory and of ports $FE, $FF and $F4. The other core reads that copy and draws a 640×480 VGA picture from it, 60 times a second.

This tells you what PicoVideo can and can't show:

  • It sees writes, not reads. PicoVideo's copy of video memory only changes when the Z80 writes to it. Register $48 (section 12) reads the copy back.
  • It only copies the home bank. If a program pages a dock or EXROM bank into 4000h–5FFFh or 6000h–7FFFh (bits 2 and 3 of port $F4), PicoVideo ignores writes to that part of memory until it is paged back.
  • Its timing is its own. The picture is redrawn by the Pico, not in step with the TS2068's television scan. Tricks timed to the beam don't line up: the border stripes during LOAD and SAVE look different, and effects that change the border or colors partway down the screen don't appear (section 2).
  • It keeps its settings. PicoVideo's registers aren't cleared by NEW or by a program ending. If a program changes a register, it should put it back when it is done.

The screen

PicoVideo shows the 256×192 TS2068 screen at 2× (512×384), centered in the 640×480 VGA picture, with the border color around it. Modes 6 and 7 use the same area at 512 pixels across. Mode 5 (80 columns) is 640 pixels wide and fills the screen from side to side.

FLASH swaps INK and PAPER every 32 VGA frames, about once every half second. With the ULAplus palette on, the FLASH bit picks colors instead and nothing flashes.

04Talking to PicoVideo

PicoVideo answers on two ports, the same ones a ULAplus Spectrum uses. Write a register number to port $BF3B (48955), then read or write the register's value at port $FF3B (65339). Both ports are decoded on all 16 address bits, so they don't clash with anything else on the bus.

PortDecimalWriteRead
$BF3B48955Select a registerThe selected register number
$FF3B65339Set the selected registerThe selected register's value, or 255 if it can't be read

In BASIC this is a pair of OUTs. Here register 66 is set to 1:

OUT 48955,66: OUT 65339,1

and register 64 is read:

OUT 48955,64: PRINT IN 65339

Finding the board and its version

Register 127 ($7F) holds the firmware version as two hex digits: $43 (67) is 4.3. A board that's present also reads the selected register back from port 48955, which an empty bus does not.

detect.bas

10 REM Detect PicoVideo and read its firmware version
20 OUT 48955,127
30 IF IN 48955<>127 THEN PRINT "No PicoVideo found": STOP
40 LET v=IN 65339
50 PRINT "PicoVideo firmware ";INT (v/16);".";v-16*INT (v/16)
60 IF v<66 THEN PRINT "Registers 66-72 need 4.2 or later"

Firmware V4 (4.0) reports 1.0 here, because its version register was never updated.

From C

The C examples in this manual use a small header, picovideo.h, written for z88dk. Build each example with zcc +ts2068 -create-app -o name name.c; that makes a .tap with a BASIC loader.

picovideo.h

/* picovideo.h - PicoVideo register helpers for z88dk (zcc +ts2068) */
#ifndef PICOVIDEO_H
#define PICOVIDEO_H
#include <stdlib.h>

#define PV_SELECT  0xBF3B   /* write the register number here */
#define PV_DATA    0xFF3B   /* then read or write its value here */

#define PV_ULA_ENABLE   0x40
#define PV_MODE         0x41
#define PV_SPECCY_BLACK 0x42
#define PV_MIRROR       0x43
#define PV_INDEX_LO     0x44
#define PV_INDEX_HI     0x45
#define PV_FONT_DATA    0x46
#define PV_QUAD_COLOR   0x47
#define PV_VIDEO_READ   0x48
#define PV_VERSION      0x7F

#define DF1 ((unsigned char *)0x4000)
#define DF2 ((unsigned char *)0x6000)

void pv_write(unsigned char reg, unsigned char value)
{
    outp(PV_SELECT, reg);
    outp(PV_DATA, value);
}

unsigned char pv_read(unsigned char reg)
{
    outp(PV_SELECT, reg);
    return inp(PV_DATA);
}

/* Set the video mode in port $FF, keeping bits 3-7 as they are. */
void pv_mode(unsigned char mode)
{
    outp(0xFF, (inp(0xFF) & 0xF8) | mode);
}

#endif

From machine code

Both ports have $3B as the low byte, so OUT (C),r with C=$3B reaches either one; only B changes. Don't use OTIR or INIR to send blocks: they count in B, which is the top half of the port address.

picovideo.asm

; picovideo.asm - PicoVideo register routines in Z80 assembler
; Assemble with any Z80 assembler (tested with sjasmplus).

PV_SELECT   equ $BF3B       ; register number goes here
PV_DATA     equ $FF3B       ; then the value goes here

; Write E to PicoVideo register D. Destroys BC.
pvWrite:
        ld      bc,PV_SELECT
        out     (c),d
        ld      b,high PV_DATA  ; same low byte, so only B changes
        out     (c),e
        ret

; Read PicoVideo register D into A. Destroys BC.
pvRead:
        ld      bc,PV_SELECT
        out     (c),d
        ld      b,high PV_DATA
        in      a,(c)
        ret

; Set video mode A (0-7) in port $FF, keeping bits 3-7. Destroys B.
pvMode:
        ld      b,a
        in      a,($FF)
        and     $F8
        or      b
        out     ($FF),a
        ret

; Load a whole 2048-byte font from HL into the 80-column font.
; Don't use OTIR here: it counts in B, which is half of the port address.
pvLoadFont:
        ld      de,$4400        ; D = register $44, E = 0
        call    pvWrite         ; font index low byte = 0
        inc     d               ; register $45
        call    pvWrite         ; font index high byte = 0
        ld      d,$46
        ld      bc,PV_SELECT
        out     (c),d           ; select the font data register
        ld      b,high PV_DATA
        ld      de,2048
.next:  ld      a,(hl)
        out     (c),a           ; the index steps on by itself
        inc     hl
        dec     de
        ld      a,d
        or      e
        jr      nz,.next
        ret

05The TS2068 modes

A program picks the video mode with the low three bits of port $FF. PicoVideo watches the same port, so the TS2068's own modes work as they always have, and PicoVideo adds three new ones in the numbers the TS2068 doesn't use.

ModeShowsMemory usedSection
0Normal 32-column screenDF1: pixels 4000h, attributes 5800h—
1Normal screen from the second display fileDF2: pixels 6000h, attributes 7800h—
2Extended color: an attribute for every pixel line of every cellDF1 pixels; DF2 holds attributes at the same offsetsbelow
3New: quad color, 256×192 in 4 colorsDF1 and DF2, linear8
4Not used; shows mode 0——
5New: 80×24 text with attributesDF1 only, linear10
664 columns, one INK and PAPER for the screenDF1 even columns, DF2 odd columns9
7New: 64 columns with attributesDF1 and DF2, each with its own attributes9

To change mode, keep the other bits of port $FF as they are. Bits 3–5 set the mode 6 colors, bit 6 turns the TS2068's interrupts off and bit 7 selects the dock or EXROM. In BASIC those bits are normally all 0, so OUT 255,mode is safe; from machine code, read the port first, as pv_mode() and pvMode do in section 4.

Mode 6 colors

In mode 6 the whole screen has one INK and PAPER, set by bits 3–5 of port $FF: INK is that number and PAPER is 7 minus it. OUT 255,6+8*n chooses INK n. BRIGHT is always off. With n=0, the default, the screen is black on white.

Display file 2 and BASIC

Modes 1, 2, 3, 6 and 7 read DF2, at 6000h–7AFFh. In a TS2068 set up for one display file, that memory holds the machine stack, the system's RAM-resident code, the channel information and the start of your BASIC program. PicoVideo copies every write there, so in those modes you see BASIC's workings as noise on screen. To use DF2 from BASIC, the TS2068 must first be set up for two display files, which moves the BASIC areas up to 7B00h (see Appendix C of the TS2068 Technical Manual). Machine code and C programs that start above 8000h can simply write to DF2, as the examples here do.

Extended color example

Mode 2 gives each 8-pixel line of each character cell its own attribute. The attribute for the pixel byte at DF1 address a is at a + 2000h.

mode2.c

/* mode2.c - TS2068 extended color (mode 2): an attribute for every
   pixel line of every character cell */
#include <stdio.h>
#include <string.h>
#include "picovideo.h"

/* offset of pixel line y, byte x, in the usual TS2068 layout */
unsigned int lineofs(unsigned char y, unsigned char x)
{
    return ((y & 0xC0) << 5) | ((y & 7) << 8) | ((y & 0x38) << 2) | x;
}

main()
{
    unsigned char *font = (unsigned char *)(*(unsigned int *)23606);
    unsigned char y, x;
    char *msg = "  EXTENDED COLOR:  MODE 2       ";  /* 32 chars */

    for (y = 0; y < 192; y++)
        for (x = 0; x < 32; x++) {
            unsigned int o = lineofs(y, x);
            unsigned char ch = (y & 8) ? ' ' : msg[x];  /* alternate rows */
            DF1[o] = font[ch * 8 + (y & 7)];           /* pixels */
            DF2[o] = 0x40 | (1 + ((y + x) >> 1) % 7);  /* BRIGHT INK */
        }

    pv_mode(2);
    while (getk()) ;  while (!getk()) ;
    pv_mode(0);
}

06Colors and Speccy Black

Without the ULAplus palette, PicoVideo draws the TS2068's 16 colors (8, and 8 BRIGHT) from a built-in table.

The photo-matched palette

Firmware 4.3 is built with a palette measured from a real TS2068's RGB output on the same monitor, so the picture looks like the computer's own. It changes the eight normal colors and the border; the BRIGHT colors are unchanged. It also starts with Speccy Black on, and the border starts white. Firmware built with PICOVIDEO_PHOTO_PALETTE=OFF uses the original colors and starts with Speccy Black off.

Speccy Black

On a ZX Spectrum, BRIGHT black looks the same as black, and Spectrum programs often use it freely. A TS2068 shows BRIGHT black as dark gray, so those programs show gray patches and outlines. With Speccy Black on, PicoVideo draws BRIGHT black as black. Register 66 ($42) controls it: any value other than 0 turns it on, 0 turns it off.

OUT 48955,66: OUT 65339,1: REM Speccy Black on
OUT 48955,66: OUT 65339,0: REM off: BRIGHT black is gray

07The ULAplus palette

PicoVideo follows the ULAplus standard used on the ZX Spectrum. With the palette on, each attribute picks its colors from a table of 64 that you load, instead of the fixed 16.

How attributes pick colors

The 64 entries are four color tables (CLUTs) of 16. The FLASH and BRIGHT bits of an attribute choose the table, so they no longer flash or brighten. Within a table, entries 0–7 are the eight INK colors and 8–15 the eight PAPER colors.

FLASHBRIGHTTableINK entriesPAPER entries
00CLUT 00–78–15
01CLUT 116–2324–31
10CLUT 232–3940–47
11CLUT 348–5556–63

So INK 3; BRIGHT 1 uses entry 16+3 = 19, and PAPER 2; FLASH 1 uses entry 32+8+2 = 42. The border uses the PAPER colors of CLUT 0: BORDER 4 shows entry 12.

Loading and switching on

  • Registers 0–63 are the palette entries. Each holds a color byte: 32×green + 4×red + blue, with green and red 0–7 and blue 0–3. They can be read back.
  • Register 64 ($40) switches the palette on (any value but 0) or off (0). It can be read back.
Load firstEvery palette entry is 0 (black) when PicoVideo starts. Switch the palette on before you load it and the whole screen goes black.

This program fills the four tables, draws a bar for every entry and then switches the palette on. CLUT 0 and CLUT 1 are close to the TS2068's own colors; CLUT 2 is a gray ramp and CLUT 3 a rainbow and a sunset.

08Quad color (mode 3)

Mode 3 draws a 256×192 screen where every pixel can be any of four colors. It has no attributes. Each pixel is two bits, and each line takes 32 bytes from DF1 and 32 from DF2:

  • Pixel line y starts at 4000h + 32y in DF1 and 6000h + 32y in DF2. Memory is in order, top to bottom, without the TS2068's interleaving.
  • Pixels 0–3 of each 8-pixel group come from the DF1 byte, pixels 4–7 from the DF2 byte.
  • Within a byte, bits 7–6 are the leftmost pixel and bits 1–0 the rightmost.

The four colors

Register 71 ($47) holds the four colors, as color bytes. Set the index to 0 with register 68 ($44), select register 71 and write four values; the index steps on after each one. They start as black (0), white (255), green (224) and yellow (252).

OUT 48955,68: OUT 65339,0
OUT 48955,71: OUT 65339,2: OUT 65339,199: OUT 65339,59: OUT 65339,252

Register 71 can be read back the same way. Mode 3 needs DF2, so draw in it from machine code or C (see section 5).

mode3.c

/* mode3.c - quad-color mode: 256 x 192 pixels in 4 colors */
#include <stdio.h>
#include <string.h>
#include "picovideo.h"

/* Mode 3 maps memory linearly: 32 bytes a line, 2 bits a pixel.
   Pixels 0-3 of each 8-pixel group come from DF1, 4-7 from DF2. */
void plot4(unsigned char x, unsigned char y, unsigned char color)
{
    unsigned char *p = ((x & 4) ? DF2 : DF1) + y * 32 + (x >> 3);
    unsigned char shift = 6 - 2 * (x & 3);

    *p = (*p & ~(3 << shift)) | (color << shift);
}

main()
{
    unsigned char x, y;
    unsigned int dy2, d;
    int dx, dy;

    /* the four colors, in the G3R3B2 byte format */
    pv_write(PV_INDEX_LO, 0);           /* start at entry 0 */
    outp(PV_SELECT, PV_QUAD_COLOR);
    outp(PV_DATA, 0x02);                /* 0: dark blue */
    outp(PV_DATA, 0xC7);                /* 1: cyan      */
    outp(PV_DATA, 0x3B);                /* 2: magenta   */
    outp(PV_DATA, 0xFC);                /* 3: yellow    */

    memset(DF1, 0, 6144);
    memset(DF2, 0, 6144);
    pv_mode(3);

    /* rings around the center of the screen */
    for (y = 0; y < 192; y++) {
        dy = y - 96;  dy2 = dy * dy;
        x = 0;
        do {
            dx = x - 128;
            d = (dx * dx + dy2) >> 8;
            plot4(x, y, (d >> 2) & 3);
        } while (++x);
    }

    while (getk()) ;  while (!getk()) ;
    pv_mode(0);
}

0964 columns in color (mode 7)

The TS2068's own 64-column mode (6) has 512 pixels across, but one INK and PAPER for the whole screen. Mode 7 uses the same pixel layout and adds the attribute areas of both display files, so every column has its own INK, PAPER and BRIGHT, like a 32-column screen.

  • Even columns (0, 2, 4…) use DF1: column c is byte c/2 of a normal screen line at 4000h, with its attribute at 5800h.
  • Odd columns use DF2 in the same way, at 6000h and 7800h.

A program written for mode 6 shows in mode 7 with whatever happens to be in the attribute areas, so switch to mode 7 only when you have filled them. The example uses the ROM character set, found through the CHARS system variable at 23606.

mode7.c

/* mode7.c - 64 columns with an attribute for every column (mode 7) */
#include <stdio.h>
#include <string.h>
#include "picovideo.h"

/* Even columns live in DF1, odd columns in DF2, each with its own
   bitmap and attribute area laid out like the normal screen. */
void put64(unsigned char col, unsigned char row, unsigned char ch, unsigned char attr)
{
    unsigned char *font = (unsigned char *)(*(unsigned int *)23606) + ch * 8;
    unsigned char *base = (col & 1) ? DF2 : DF1;
    unsigned char *pix  = base + ((row & 0x18) << 8) + ((row & 7) << 5) + (col >> 1);
    unsigned char line;

    for (line = 0; line < 8; line++)
        pix[line * 256] = font[line];
    base[0x1800 + row * 32 + (col >> 1)] = attr;
}

void print64(unsigned char col, unsigned char row, char *s, unsigned char attr)
{
    while (*s) put64(col++, row, *s++, attr);
}

main()
{
    unsigned char c;

    memset(DF1, 0, 6144);  memset(DF1 + 6144, 0x38, 768);  /* PAPER 7, INK 0 */
    memset(DF2, 0, 6144);  memset(DF2 + 6144, 0x38, 768);

    print64(0, 0, "  PicoVideo mode 7: 64 columns, an attribute for every column  ", 0x4F);
    print64(2, 2, "Mode 6 gives the whole 64-column screen one INK and PAPER.", 0x38);
    print64(2, 3, "Mode 7 uses the attribute areas of both display files, so", 0x38);
    print64(2, 4, "every column has its own. Even columns are DF1, odd are DF2.", 0x38);

    for (c = 0; c < 64; c++) {
        put64(c, 7, ' ', (c & 7) << 3);                  /* PAPER 0-7 */
        put64(c, 8, ' ', ((c & 7) << 3) | 0x40);         /* BRIGHT */
        put64(c, 10, 'A' + (c % 26), 0x40 | (1 + c % 7));      /* on PAPER 0 */
        put64(c, 11, '0' + (c % 10), ((7 - (c & 7)) << 3) | (c & 7));
    }

    print64(2, 14, "10 REM mode 7 listing", 0x38);
    print64(2, 15, "20 FOR i=0 TO 63: PRINT AT 0,i;CHR$ (65+i): NEXT i", 0x38);
    print64(2, 16, "30 STOP", 0x38);
    print64(2, 19, "Press a key for mode 6 (one color pair), then again to exit.", 0x30);

    pv_mode(7);
    while (getk()) ;  while (!getk()) ;
    pv_mode(6);
    while (getk()) ;  while (!getk()) ;
    pv_mode(0);
}

1080-column text (mode 5)

Mode 5 is a text screen of 80 columns and 24 rows. You store character codes, not pixels; PicoVideo draws them with its own 8×8 font, which starts as the IBM PC (code page 437) set with box drawing, shading and accented letters. Each character has its own attribute, in the usual TS2068 format.

WhatAddressFormula
Character code4000h–477Fh (16384–18303)16384 + 80×row + column
Attribute4780h–4EFFh (18304–20223)18304 + 80×row + column

Mode 5 uses only the first 3840 bytes of DF1, so it works from BASIC. It doesn't touch the bottom third of the TS2068's screen memory, where BASIC prints its reports. CLS fills the area with 0, which is a blank in black on black, so fill the attributes before you print. Text in this mode fills the full 640-pixel width of the monitor.

220 FOR i=1 TO LEN a$
230 POKE a,CODE a$(i): POKE a+1920,t: LET a=a+1
240 NEXT i: RETURN

Filling 1920 attributes one POKE at a time takes BASIC a while; the example takes about half a minute to draw. For real programs, use machine code or C.

The text80 library

The repository's examples/text80/ folder has a ready-made library for this mode, in z88dk C and in Z80 assembler: clear the screen, set the cursor, print characters and strings, change attributes and load the font. text80.tap there is a demo.

11Changing the font

The 80-column font is 2048 bytes in the Pico's memory: 256 characters of 8 bytes, top row first, with bit 7 as the leftmost pixel. Character c starts at byte 8c.

  1. Write the low byte of the start address to register 68 ($44) and the high byte to register 69 ($45).
  2. Select register 70 ($46) and write the bytes. The address steps on after each one, and wraps from 2047 to 0.

Reading register 70 returns font bytes the same way, so you can save a font or check one. This program redefines characters 128 and 129 as two halves of an arrow and reads a row back:

font80.bas

10 REM Redefine characters in the 80-column font
20 FOR c=128 TO 129
30 LET a=c*8
40 OUT 48955,68: OUT 65339,a-256*INT (a/256)
50 OUT 48955,69: OUT 65339,INT (a/256)
60 OUT 48955,70
70 FOR i=1 TO 8: READ b: OUT 65339,b: NEXT i
80 NEXT c
90 DATA 0,3,15,63,255,63,15,3
100 DATA 0,192,240,252,255,252,240,192
110 REM read the first row of character 128 back
120 OUT 48955,68: OUT 65339,0: OUT 48955,69: OUT 65339,4
130 OUT 48955,70: PRINT "Row 0 of character 128: ";IN 65339

To load a complete font from memory, use pvLoadFont in picovideo.asm (section 4). The font is in the Pico's RAM: a change lasts until PicoVideo is switched off, and then it goes back to code page 437.

One index for three registersRegisters 70 (font), 71 (quad colors) and 72 (video memory) all share the index set by registers 68 and 69. Set the index again whenever you switch from one to another.

12Mirroring and readback

Writing DF2 through DF1

Register 67 ($43) turns mirroring on (any value but 0) or off (0). While it is on, writes to 4000h–5FFFh go into PicoVideo's copy of DF2 instead of DF1. The TS2068's own memory still changes as usual; only PicoVideo's copy is different. This lets routines that only know DF1, such as the ROM's PRINT and PLOT, draw into DF2 for modes 3, 6 and 7.

Mirroring chooses where writes go, not what is shown: set the display mode separately. Writes to 6000h–7FFFh still reach DF2, so the warning about BASIC in section 5 still applies. Register 67 can be read back.

Reading video memory

The TS2068 can't read PicoVideo's copy of the screen with PEEK. Register 72 ($48) can: set the index with registers 68 and 69, select 72, and each IN returns one byte and steps on. Index 0 is address 4000h, index 8192 is 6000h.

This program writes one byte with mirroring on, then compares PicoVideo's DF1, its DF2 and the TS2068's own memory. On a PicoVideo it prints 0, 170 and 170.

mirror.bas

10 REM DF2 mirroring and memory readback
20 CLS
30 OUT 48955,67: OUT 65339,1: REM mirror on
40 POKE 16384,170
50 OUT 48955,67: OUT 65339,0: REM mirror off
60 LET o=0: GO SUB 900: PRINT AT 2,0;"PicoVideo DF1 byte 0: ";v
70 LET o=8192: GO SUB 900: PRINT "PicoVideo DF2 byte 0: ";v
80 PRINT "TS2068 RAM at 16384: ";PEEK 16384
90 STOP
900 REM read PicoVideo memory at offset o (0 = address 16384)
910 OUT 48955,68: OUT 65339,o-256*INT (o/256)
920 OUT 48955,69: OUT 65339,INT (o/256)
930 OUT 48955,72: LET v=IN 65339: RETURN

13Pinning the mode

Register 65 ($41) lets you fix the video mode so that writes to port $FF no longer change it. It only works while the ULAplus palette is on (register 64 not 0); with the palette off, port $FF always sets the mode.

Register 65Video mode
0Follows port $FF, as normal. This is the starting value.
128 ($80)Fixed at mode 0.
anything elseFixed at the mode in the low four bits: 5 pins 80 columns, 7 pins 64 columns.

Because the palette has to be on, load one first. This example loads the TS2068's own colors into all four tables, pins mode 5 and shows that OUT 255,0 no longer changes the mode. Register 65 can be read back.

pinmode.bas

10 REM Pin the video mode with register 65 ($41)
20 FOR c=0 TO 63
30 LET i=c-8*INT (c/8): LET b=INT (c/16)-2*INT (c/32)
40 RESTORE 200+10*b: FOR j=0 TO i: READ v: NEXT j
50 OUT 48955,c: OUT 65339,v
60 NEXT c
70 OUT 48955,64: OUT 65339,1: REM ULAplus on, TS2068 colors loaded
80 OUT 48955,65: OUT 65339,5: REM pin mode 5 (80 columns)
90 OUT 255,0: REM ignored while the mode is pinned
100 OUT 48955,65: PRINT "Register 65 = ";IN 65339
110 PAUSE 0
120 OUT 48955,65: OUT 65339,0: REM follow port 255 again
130 OUT 48955,64: OUT 65339,0: REM ULAplus off
140 STOP
200 DATA 0,2,16,18,128,130,144,146
210 DATA 0,3,28,31,224,227,252,255
Older firmwareIn 4.2 and earlier, with the palette on, register 65 always set the mode, so 0 meant mode 0. In 4.3, write 128 to get that.

Color bytes

Palette entries, quad colors and the color tables all use one byte per color, in the ULAplus layout: bits 7–5 green, 4–2 red, 1–0 blue.

color = 32*green + 4*red + blue     green 0-7, red 0-7, blue 0-3

Some values: black 0, blue 3, red 28, magenta 31, green 224, cyan 227, yellow 252, white 255, mid gray 146.

15Updating the firmware

PicoVideo's behavior lives in the Pico's firmware, a single .uf2 file. Releases are on the project's GitHub releases page.

VersionStatusWhat it has
V4 (4.0)Stable, on production boardsTS2068 modes and ULAplus. Fixes stray pixels on boards with Atmel PLDs. Version register reads $10.
4.2BetaAdds Speccy Black, DF2 mirroring, readback, and modes 3, 5 and 7.
4.3BetaFixes for native modes under ULAplus, the ULAplus border and 64-column colors; adds the photo-matched palette. Version register reads $43.

This manual describes 4.3. Everything in sections 6 and 8 to 13 needs 4.2 or later.

Flashing the Pico

You need a USB cable with a Micro-B plug for the Pico.

  1. Switch the TS2068 off and take PicoVideo out of the bus.
  2. Hold down the BOOTSEL button on the Pico.
  3. Keep holding it while you plug the USB cable into the Pico and your computer, then let go.
  4. A drive called RPI-RP2 appears on the computer. Drag the .uf2 file onto it.
  5. The drive disappears by itself when the copy is finished. Unplug the cable and put the board back in the bus.
Check the resultThe program in section 4 prints the firmware version, so you can see that the new firmware is running.

Building the firmware yourself

The source is in the firmware/ folder of the repository. You need the Raspberry Pi Pico SDK, an arm-none-eabi GCC toolchain, CMake and Ninja:

cmake -S firmware -B build -G Ninja -DPICO_SDK_PATH=/path/to/pico-sdk
ninja -C build

That makes build/picoTsVid.uf2. The build uses the photo-matched palette (section 6). Add -DPICOVIDEO_PHOTO_PALETTE=OFF to the cmake line for the original colors.
